# Support sources

This directory preserves reusable support code from local experiments. The production Station client is in `../station/`; these diagnostic probes are historical experiments, not production services or evidence of account/device compatibility.

- `runtime/`: Linux supervisor and init templates, including offline activation-mode tests. Templates use documented device filesystem paths, root ownership checks, private configuration files, PID/start-time identity checks, and bounded restart backoff. No credentials or project IDs are included.
- `auth/`: a Windows PowerShell diagnostic for the unofficial ChatGPT web-session endpoint. Its default invocation runs synthetic tests only. It accepts an explicitly supplied curl export only with `-RequestSession`, sends a bounded GET to a fixed public endpoint, and stores sensitive packs using Windows DPAPI. It is an experiment, not a supported login or guaranteed unattended renewal mechanism. Browser-auth research and live results are omitted.
- `diagnostics/column-agent/`: a one-request HTTPS preflight for an operator-configured Sites origin. Configuration is read from standard input; output contains fixed status categories. It restricts destinations, disables redirects and core dumps, verifies TLS, and bounds response sizes. Tests use synthetic tokens and local TLS servers.
- `diagnostics/cloud-probe/`: a dependency-free MCP receipt Worker, synthetic tests, and build scripts. Tool execution requires the hosting authentication header; deploy behind an authenticated hosting boundary. Optional public DNS observations query fixed Dreame hosts through Cloudflare, with no account/device access. The hosting project identifier is intentionally unset.
- `diagnostics/kws-probe/` and `kws-offline-probe/`: separate historical keyword detector experiments. The former consumes the device's local audio IPC; the latter consumes a caller-supplied WAV fixture. Source and synthetic tests are included; recorded audio, vendor models, vendor libraries, device results, deployment scripts, and binaries are not. Identical small native wrappers are retained so each experiment builds independently.
- `diagnostics/abi/` and `kolya/`: synthetic-silence ABI and TensorFlow Lite model-format probes. The latter does not implement a working wake-word detector. The training configuration is an untrained example, not a trained model or accuracy claim.
- `provisioning/`: address-scoped HTTP/HTTPS/DNS adapter and synthetic tests. It defaults to a check, requires explicit serving and firmware arming, and validates local input artifacts. Firmware, certificates, private keys, real device configuration, root/SSH payloads, and the external eQuasar implementation are not included. See its README.
- `toolchain/`: optional historical pinned Linux tool bootstrap and a portable environment example. No installer is run when importing or checking other sources.

See `CHECKS.md` for verification and `PROVENANCE.md` for attribution and exclusions. `EXPORT_MANIFEST.json` records original source paths and packaging edits. No live network, device, account, browser, SSH, or deployment actions are required by the verification commands.
